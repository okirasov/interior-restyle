# Перенос дизайна интерьера на новую планировку

Пользователь обычно приносит 3D-сцену новой планировки и картинки дизайна (часто рендеры, сделанные под старую
планировку). Задача — собрать в Blender ту же квартиру в этом стиле, ничего не ломая в расстановке без спроса,
и выдать рендеры, PDF и, если нужно, видео-проход. Работа идёт итерациями: пользователь смотрит картинки и даёт
правки, поэтому важны скорость пробных кадров и точечный перерендер.

Скрипты скилла лежат в `scripts/` рядом с этим файлом. Сцена собирается **проектным** скриптом
`<проект>/scripts/build_scene.py`, который ты пишешь для каждой квартиры на основе `scripts/scene_lib.py`:
координаты и правила материалов у каждой квартиры свои, а функции (материалы, геометрия, свет, камеры, рендер)
общие. Так любую правку можно применить и пересобрать сцену одной командой.

## Правила работы с пользователем

Это договорённости, которые пользователь явно просил соблюдать:

- **Сначала вопросы, потом работа.** Задавай уточняющие вопросы по одному, опираясь на увиденное в файлах
  (см. «Этап 2»). Ничего не рендерь до утверждения описания задачи.
- **Любое скачивание — только после «да».** Назови файл, источник, лицензию и размер (для Poly Haven размеры
  берутся из `api.polyhaven.com/files/<id>`). Превью-картинки для выбора смотреть можно без спроса.
- **Замена моделей — только после согласования каждого предмета.** Перекраска существующих предметов — по умолчанию.
- **Перерендеривай только затронутые кадры.** Перед финальным рендером определи, какие камеры видят изменённые
  объекты, и скажи одной строкой, какие кадры обновляешь и почему. `--render all` — только если изменение видно
  везде (например, поменялся материал, который есть в каждом кадре).
- **Перед долгим рендером называй время** (замерь 1–6 кадров и умножь). Долгие рендеры запускай в фоне и не дёргай.
- **Не трогай расстановку**, если пользователь не разрешил: объекты из сцены остаются на своих местах; добавлять
  встроенную мебель (ниши, панели, ТВ-стену) — только с его согласия.
- Говори на языке пользователя, без жаргона; называй комнаты и вещи, а не объекты Blender.

## Окружение

- Blender 5.x в PATH (`blender -b --python ...`). На Mac рендер идёт на GPU через Metal.
- Для PDF и листов предпросмотра нужен Python с Pillow и reportlab: создай venv в scratchpad
  (`python3 -m venv <scratch>/pdfenv && <scratch>/pdfenv/bin/pip install reportlab pillow`) и запускай
  **всегда с `-I`**: иначе файлы в папке скрипта (например, свой `inspect.py`) подменяют модули стандартной
  библиотеки, и Pillow «не узнаёт» PNG.
- ffmpeg для склейки видео (`brew install ffmpeg`, если нет — спроси перед установкой).

## Этапы

### Этап 1. Разбор входных файлов
1. Запусти `blender -b --python scripts/inspect_scene.py -- <scene> <scratch>/inspect` → `objects.txt`
   (типы объектов с габаритами), `summary.txt`, `top.png` (план), `iso.png`. Посмотри план и изометрию.
2. Просмотри все референсы (рендеры, фото, план старой квартиры). Составь для себя: стиль (материалы, цвета,
   фурнитура, свет), список зон и элементов дизайна.
3. Сопоставь зоны «было → стало» по плану: что переносится один в один, что меняется из-за планировки.
   Имена объектов планировщика расшифрованы в `references/planner_objects.md`.

### Этап 2. Вопросы (по одному, с конкретикой из файлов)
Обязательно выясни, если не сказано:
- **Расстановка:** не трогать / можно добавлять встроенную мебель / можно двигать.
- **Предметы:** перекрасить существующие / заменить моделями (каждую согласовать).
- **Источник текстур:** Poly Haven (с подтверждением скачивания) / только процедурные / образцы из каталога пользователя.
- **Что на выходе:** рендеры (какие комнаты), PDF, видео; качество (см. таблицу ниже).
- Отличия, которые ты заметил между референсами и сценой (например, «острова не будет — будет барная стойка»).
Пересказывай понятое кусками и спрашивай, что не так. Итоговое описание — пользователь одобряет до старта.

### Этап 3. Пробные кадры
Собери стиль на 1–2 ключевых комнатах (обычно кухня + спальня). Цикл: предпросмотр `--samples 24..32 --res 640..800`
→ смотри сам (лист предпросмотра) → правь → финальный кадр `--samples 256 --res 1600`. Покажи пользователю и
спроси, совпадает ли стиль. Типичные первые правки: пересвет/недосвет, ткань с голубым оттенком (лён Poly Haven —
бери только яркость, `desat`), рамочные фасады из каталога вместо гладких (`flatten_front`).

### Этап 4. Все комнаты и все точки
Камеры: на каждую комнату 1–2 вида на высоте 1.3–1.6 м, объектив 16–20 мм; санузел — вертикальные кадры 3:4
(14–16 мм, камера в проёме двери или у раковины); плюс изометрии (со стороны окон и со стороны входа, потолки
скрыты) и ортогональный план. Список видов держи в словаре `VIEWS` проектного скрипта. Сначала предпросмотр всех
видов листами, потом финал в фоне.

### Этап 5. Правки
Каждую правку вноси в проектный скрипт (а не в .blend руками) и пересобирай сцену. Перерендер — только затронутые
кадры. Если пользователь передумал («верни как было») — возвращай прежние параметры, а не придумывай третий вариант.

### Этап 6. PDF
`scripts/make_pdf.py <config.json> <out.pdf>` — обложка с изометрией, разделы по комнатам, подпись к каждому
кадру (материалы и решения: «Дуб Небраска», «плитка 60 × 120» и т. п.). Формат конфига — в шапке скрипта.
Проверь страницы, растеризовав (`pdftoppm -r 40`), прежде чем отдавать.

### Этап 7. Видео-проход
1. Согласуй маршрут словами (вход → … → финальный кадр) и длительность.
2. Запиши маршрут в `route.json` (формат — в шапке `scripts/walkthrough.py`), проверь `--analyze`:
   поворот ≤ ~45°/с, скорость ≤ ~0.8 м/с. Если пользователь хочет короче — убирай лишние повороты, а не сжимай
   время (сжатие ускоряет повороты и видео «дёргается»).
3. `--stills` — контрольные кадры в точках маршрута; проверь, что камера не утыкается в стены и мебель.
4. Черновик EEVEE (960 px, ~1.5 с/кадр) → пользователь проверяет маршрут → финал Cycles 720p
   (~11 с/кадр при 96 сэмплах; motion blur включён по умолчанию). На время рендера держи Mac бодрствующим:
   `caffeinate -i -w <pid blender> &`.
Подробности и причины рывков — `references/video.md`.

## Качество и время (Mac M4 Pro, Metal, kernel optimization OFF)

| Режим | Параметры | Время на кадр |
|---|---|---|
| Предпросмотр | 640–800 px, 24–32 сэмпла | 2–5 с |
| Стандарт | 1600 × 1200, 256 сэмплов | ~70 с |
| Высокое | 2560 × 1920, 512 сэмплов | ~6 мин |
| 4K | 3840 × 2880, 1024 сэмпла | ~25 мин |
| Видео черновик | EEVEE 960 × 540 | ~1.5 с |
| Видео финал | Cycles 1280 × 720, 96 сэмплов | ~11 с |

Если пользователь просит «высокое качество», честно скажи, что упрощённые модели (собранные из коробок и модели
каталога) на 4K станут заметнее, и предложи сначала заменить ключевые предметы детальными моделями.

## Справочники

- `references/pitfalls.md` — **прочитай перед первой сборкой**: известные грабли Blender 5.x/Cycles и как их обходить
  (падение на Metal, чёрный потолок, чёрное стекло, искажённые скругления, area-лампы в кадре).
- `references/materials.md` — рецепты материалов: подгонка цвета под образец каталога, ламинат из фото,
  плитка заданного размера, фотообои, ткани, металлы; Poly Haven API.
- `references/planner_objects.md` — расшифровка имён объектов онлайн-планировщика (ward, kitchen_box_*, …)
  и какие части у них фасады, ручки, корпус.
- `references/video.md` — видео-проход: маршрут, плавность, время рендера.

## Шаблон проектного скрипта

```python
import bpy, sys, os
sys.path.insert(0, os.path.expanduser("~/.claude/skills/interior-restyle/scripts"))
import scene_lib as L
ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
argv = sys.argv[sys.argv.index("--") + 1:] if "--" in sys.argv else []
arg = lambda n, d=None: argv[argv.index(n) + 1] if n in argv else d

L.init(root=ROOT, tex_dir=os.path.join(ROOT, "textures"))
meshes = L.import_scene(os.path.join(ROOT, "<сцена>.glb"))
L.M.update({...})                    # материалы проекта: L.solid / L.textured / L.tiles / L.photo_planks ...
for o in meshes:                     # правила по именам объектов -> материал / скрыть / гладкий фасад
    t, part, name = L.parse(o.name)
    ...
# добавленная геометрия: потолки (без перекрытий!), встроенная мебель, свет, камеры
L.sky_world(); L.sun(); ...
L.setup_cycles(samples=int(arg("--samples", "256")))
VIEWS = {"01_kitchen": ((x, y, 1.45), (tx, ty, 1.25), 17, ()), ...}
bpy.ops.wm.save_as_mainfile(filepath=os.path.join(ROOT, "<имя>.blend"))   # сохранить ДО рендера
which = [v for v in (arg("--render", "") or "").split(",") if v]
if which: L.render_views(VIEWS, which, os.path.join(ROOT, "renders"), res=int(arg("--res", "1600")), groups=GROUPS)
```
Запуск: `blender -b --python scripts/build_scene.py -- --render 01,06 --samples 32 --res 800`.
Если пользователь сам правит .blend в интерфейсе — предупреди, что пересборка скриптом его перезапишет
(пусть сохраняет под другим именем).
